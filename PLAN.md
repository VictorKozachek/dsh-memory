# План проекта dsh-memory

**Статус:** дизайн → разработка MVP. Кода ещё нет; план ниже — очередь задач,
из которой нарезаны карточки доски (`.kanban/tasks/*.md`, спека
`.kanban/specs/001-mvp.md`).

## Цель и критерии успеха

Сделать плагин DSH, который даёт агентам долгосрочную память проекта и
каскадное расходование токенов: сначала L0 (детерминированные источники) и L1
(локальный RAG), затем L2 (дешёвая сабмодель с контрактом `ANSWER | NO_ANSWER`),
и только потом L3 (основная модель). Успешный ответ дистиллируется и после
проверки возвращается в память.

| Цель | Метрика | Планка MVP |
|---|---|---|
| Экономия токенов | токены на повторяющихся вопросах | −25% |
| Переиспользование знаний | hit-rate L1 | ≥ 20% |
| Качество | доля `verified` записей с провенансом | 100% |
| Чистота | записей без источника | 0 |
| Латентность | добавка к первому токену от инъекции | ≤ 50 мс |

## Как ведётся работа

- **Одна задача = один worktree = одна ветка `task/<id>` = одна карточка.**
  Workspace один: карточка лежит в основном чекауте, код задачи — в
  `worktrees/<id>`, worktree создаётся при выдаче от актуального `main`. Правила
  ролей и переходов — [`AGENTS.md`](AGENTS.md).
- **Лимит в работе — 3 задачи** (`in-progress` + `in-review` + `testing`);
  остальное ждёт в `backlog`, выдача по порядку id.
- **Definition of Done задачи:** код в ветке, тесты/проверки зелёные, карточка
  содержит что сделано и как проверить, ревью и тест пройдены, ветка влита
  оркестратором в `main`. Пуш в remote — шаг человека.
- Плагин ставится в профиль как обычный компонент DSH (`dsh.bundle` +
  `cordis.patch.yml`), поэтому проверка задачи включает загрузку модуля
  штатным загрузчиком DSH, а не только юнит-тесты.

## Риски

| Риск | Митигация |
|---|---|
| Галлюцинация попадает в память и тиражируется | `verified` только через ревью/тест и с источником; `draft` помечен |
| Устаревшие знания после изменений кода | инвалидация по `sha256`, TTL, `stale` не выдаётся |
| Раздувание индекса | дедупликация по `hash`, лимит сниппетов, TTL |
| Замедление хода | инъекция ≤ 50 мс, кэш поиска, флаг отключения |
| Утечка секретов в индекс | фильтры файлов и ключей, локальное хранение, только сниппеты |
| Плагин ломает ход при ошибке | все вызовы в `try/catch`, при ошибке память молчит |

## Чем план не является

- Это не обещание сроков: порядок задач задан зависимостями, а не календарём.
- Фазы 4–5 — исследовательские: их результат может изменить план, поэтому
  карточки 016–018 закрываются дизайн-документом и прототипом, а не «готовой
  функцией».
- Внутренняя спецификация проекта (подробные контракты и схема) в репозиторий
  не публикуется; публичная часть — README и этот план.
