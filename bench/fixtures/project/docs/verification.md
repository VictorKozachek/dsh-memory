# Верификация записей

В память пишется только проверенное. `memory.write` всегда создаёт `draft`;
прямая запись `verified` или `stale` через write — ошибка.

Перевод `draft` → `verified` делает `memory.verify`. Ему нужны два условия:
источник (провенанс записи или связь в `entry_sources`) и подтвердитель
`verified_by`. Подтвердитель — это PASS ревью/теста (`reviewer:…`,
`verifier:…`, `tester:…`) или человек (`human`). Голый id сессии не
принимается: иначе любая сессия, включая модель, могла бы подтвердить саму
себя.

По умолчанию источник обязателен (`verify.require_source_for_verified: true`).
Ручное исключение — только `human` с `requireSource: false`: человек может
подтвердить запись без источника вручную, но PASS ревью/теста источник
требует всегда. Иначе метрика «100% verified с провенансом» перестаёт быть
правдой.

Ответ модели (write-back каскада) создаётся как `draft` с `confidence` не выше
0.6 и автором `cascade:L2`/`cascade:L3`. Модель не подтверждает знание: её
ответ — черновик для последующей проверки. Дубль от модели не повышает и не
понижает уверенность человеческой записи.

`stale`-запись верифицировать нельзя: сначала знание перезаписывают. Повторный
verify уже подтверждённой записи идемпотентен.

## Кто и как подтверждает

Подтверждение — это социальный акт, а не вычисление. Ревьювер или тестировщик
подтверждает, что знание проверено; человек может подтвердить вручную. Плагин
не пытается угадать «истину» по тексту: он проверяет, что у подтверждения есть
источник и явный субъект.

Поэтому список подтвердителей закрытый: `human`, `reviewer`, `verifier`,
`tester`. Голый id сессии не принимается — иначе модель могла бы подтвердить
свой же ответ, и статус `verified` перестал бы что-либо значить.

Идемпотентность важна для ретраев: повторный verify не меняет запись и не
пишет лишних метрик, поэтому сетевые повторы и повторные вызовы инструмента
безопасны.
