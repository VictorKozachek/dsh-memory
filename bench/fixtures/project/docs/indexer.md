# Индексатор документации

Индексатор обходит markdown-файлы воркспейса (`**/*.md`) и пропускает
служебные каталоги: `.git`, `node_modules`, `dist`, `build`, `tmp`, `.cache` и
`worktrees`. Карточки доски `.kanban/tasks/*.md` и ADR `docs/adr/*`
индексируются как `decision` с TTL 180 дней; README компонентов и прочая
документация — как `doc` без TTL.

Чанкование идёт по заголовкам `##`: каждый раздел становится отдельным
чанком, длинные разделы режутся по абзацам и словам с пределом 800 токенов
(оценка `ceil(символов/3)`). Заголовок `#` первого уровня даёт имя файла в
title и в текст чанка не попадает.

Инкрементальность — по `sha256` содержимого и `mtime` файла. `touch` без
изменения текста не переиндексирует файл; правка содержимого — да. Изменённый
файл переиндексируется в транзакции: старые чанки становятся `stale`, новые
вставляются или возвращаются из `stale` по тому же hash. Если транзакция
упала, старые чанки остаются на месте, источник не обновляется, следующий
прогон повторяет. Записи `memory.write` с тем же `source_path` индексатор не
трогает.

Файл, которого больше нет в обходе (удалён, исключён или стал секретом),
теряет источник, а его чанки становятся `stale`; текст остаётся в базе для
аудита, но поиском не выдаётся. Удаление источников работает в пределах
namespace.

Секреты отсеиваются по имени (`*.env`, `*secret*`, `*credential*`) и по форме
ключа (PEM, `ghp_`, `sk-`, `AKIA`); путь отсеянного файла попадает в отчёт
`secrets`.

## Атомарность и отчёты

Переиндексация одного файла идёт в транзакции: либо все новые чанки записаны и
источник обновлён, либо всё откатилось. Это защищает от полуфайла в памяти,
когда часть разделов новая, а часть старая. Сбой одного файла не мешает
остальным: отчёт собирает `failed`, а следующий прогон повторяет.

Отчёт индексации — машинно-читаемый: `files`, `indexed`, `unchanged`,
`skipped`, `chunks`, `revived`, `stale`, `removed`, `secrets`, `failed`.
По нему видно, что изменилось, и его удобно сравнивать между прогонами.

Фронтматтер карточек пока индексируется как текст; это осознанно оставлено на
отдельное решение, чтобы не терять метаданные решений молча.
