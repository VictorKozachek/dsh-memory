# Namespace и изоляция памяти

Namespace — это имя памяти, обычно совпадающее с воркспейсом. Каждый namespace
хранится в отдельном файле `<db_path>/<namespace>.db`, поэтому память разных
проектов не смешивается: поиск, дедупликация и TTL работают в рамках одного
namespace.

`namespace: auto` — не «имя сейчас», а правило: оно разрешается в имя каталога
воркспейса в момент, когда воркспейс известен. У каждой сессии DSH свой
рабочий каталог, поэтому одно и то же правило даёт разные namespace разным
проектам.

`DSH_MEMORY_DB` перекрывает каталог баз; `--namespace` в CLI и
`namespace` в конфиге — явное имя. Если один namespace использовать для разных
воркспейсов, индексатор сочтёт файлы «чужого» воркспейса исчезнувшими и
помечит их `stale`: namespace должен соответствовать воркспейсу.

Провенанс записей хранит относительные пути от корня воркспейса, поэтому
перенос проекта в другой каталог не ломает источники. Абсолютные пути в память
не пишутся.

Изоляция — это и про приватность: секреты одного проекта не попадают в поиск
другого, даже если оба используют один `db_path`. Штатный режим — один
namespace на воркспейс, `namespace: auto` делает это поведением по умолчанию.

## Имена и миграции

Переименование namespace — это новая память: старый файл остаётся под старым
именем. Автоматической миграции в MVP нет, потому что смешение проектов хуже
потери истории; перенос делается копированием файла вручную.

`namespace: auto` использует basename каталога, а не git-remote: у одного
проекта может быть несколько воркспейсов (основной чекаут и worktree), и это
нормально — у каждого своя память. Для общих знаний между worktree нужен
явный namespace в конфиге.

Провенанс относителен воркспейсу, поэтому при смене namespace старые пути
могут не найтись. Это ещё одна причина не переименовывать namespace без
необходимости.
