# Мягкий каскад L0 → L3

Каскад экономит токены: сначала бесплатные детерминированные источники (L0),
затем RAG-память (L1), затем дешёвая сабмодель (L2) и только при отказе —
основная модель (L3).

L0 — доска задач, карточки и `grep`/`glob` по файлам: 0 токенов модели.
L1 — top-k сниппетов из SQLite FTS5: тоже 0 токенов модели, но добавляет
несколько сотен токенов в контекст. L2 — дешёвая модель по пресету `triage`:
она отвечает по контракту `ANSWER | NO_ANSWER`, только если уверена. L3 —
основная модель из настроек сессии; вызывается только после `NO_ANSWER` на L2.

Пресет `triage` описан в `presets/triage.json`: дешёвая модель
`deepseek-v4-flash`, `maxTokens` 300, контракт `ANSWER | NO_ANSWER`. Конфиг
`cascade.enabled` включает L2, `cascade.model` перекрывает модель пресета.
Если каскад выключен, память всё равно ищется, а затем сразу вызывается L3.

После ответа L2 или L3 дистиллят пишется в память как `draft` с источником
(write-back). `verified` ставится только отдельной проверкой. Ответ модели
имеет `confidence` не выше 0.6, чтобы не выглядеть проверенным знанием.

Ошибки памяти и записи не ломают ход: каскад продолжает отвечать, а запись
просто не происходит. Решения каскада пишутся в метрики как `route` с полями
`layer`, `reason`, `tokens_saved_estimate` и `injected_tokens`.

## Почему каскад «мягкий»

«Мягкий» означает, что решение о слое не жёсткое: L2 может отказаться
(`NO_ANSWER`) и передать ход L3, а L1 может не найти ничего и не блокировать
ответ. Жёсткий роутер, который всегда выбирает один слой, экономит больше, но
рискует качеством; мягкий каскад предпочитает качество и постепенно
калибруется бенчмарком.

Порог уверенности L2 задаётся промптом пресета, а не жёстким числом: модель
сама решает, хватает ли ей контекста. Ответ L2 стоит дешевле L3, но его
качество ниже, поэтому write-back всегда идёт как `draft` — знание проверит
ревью или тест.

Слой L0 (детерминированные источники) остаётся за агентом: доска, карточки,
`grep` и `glob`. Плагин не отменяет их, а дополняет L1. Если агент уже нашёл
ответ в файлах, память может не понадобиться; задача памяти — не мешать, а
подсказывать.
