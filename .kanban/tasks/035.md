## Задача
Регистрация memory.* дождаться сервиса tools (live-профиль)

Найдено оркестратором при живой проверке: плагин в профиле desktop загружается
(создаётся `~/.dsh/memory/dsh-memory.db`, модель скачана), но в tool-list агента
нет `memory.*`. Причина: в `lib/index.js` регистрация вызывается сразу в `apply`,
проверяет `ctx.tools ?? ctx.get('tools')` и при недоступности молча пропускает;
сервис `tools` появляется позже, и повторной попытки нет.

## Критерии готовности
- [ ] в живом профиле desktop инструменты memory.search/write/verify/invalidate/stats попадают в tool-list агента новой сессии (проверить по request/header в логе сессии)
- [ ] регистрация не привязана к моменту apply: применяется через ctx.inject(['tools'], …) или эквивалент, дожидаясь сервиса tools; при отсутствии tools плагин грузится как раньше (fallback, без падения)
- [ ] юнит-тест: tools появляется после apply (поздняя инъекция) → инструменты регистрируются; без tools — нет исключения
- [ ] живая проверка на реальном ToolRuntime/профиле: инструменты видны агенту и вызываются; повторный apply не дублирует регистрацию
- [ ] README/тестовая документация: поведение «tools опционален» описано честно
