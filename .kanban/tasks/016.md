  Возврат: есть функциональный блокер в гибридном канале и два недоделанных критерия. 1) Канал эмбеддингов не работает с хранилищем текущего поиска: createLocalChannel замыкает store, переданный при создании, а channel.search({ store, query, ... }) аргумент store игнорирует; apply опционального пакета создаёт канал на memory.storeFor(process.cwd()) — это не воркспейс сессии. Воспроизвёл: store A (namespace A, запись id=1 «Индексатор»), store B (namespace B, запись id=1 «Память», без слова «индексатор»); channel создан на A; searchMemory(B, {query:'индексатор'}, {channels:[channel]}) возвращает запись B id=1 «Память», а без канала — []; потому что хит канала id=1 из A резолвится в B по совпавшему id. Это не просто «канал пуст» — гибридный поиск подмешивает чужие/нерелевантные записи при любом совпадении id между namespace. Нужно: channel.search брать store из аргумента и работать только с ним (или регистрировать канал на каждый store/сессию), apply не должен открывать store по process.cwd() для backfill; backfill — по store сессии/воркспейса. Добавить тест с двумя store/namespace и пересекающимися id, плюс тест, что канал не подмешивает записи из другого store.
  
  2) API/Ollama не дают гибридного поиска: apply регистрирует канал только для provider.kind === 'local'; для openai-compatible/ollama он лишь пишет info и делает backfill. То есть пользователь, включивший API-бэкенд (критерий 3), не получает гибридный скор (критерий 4) — векторы считаются, но в выдаче не используются. В заметке это названо ограничением «async query-канал — следующий шаг», но карточка 016 требует реализации, а не следующего шага. Нужно либо async-канал (например, асинхронный query-путь с precomputed query-эмбеддингом/кэшем и ожиданием с таймаутом), либо явное решение оркестратора, что API-канал в 016 только backfill (тогда критерий 4 надо сузить и зафиксировать).
  
  3) Критерий 2 «бэкенд локальной модели»: local-провайдер — детерминированный хэш слов/триграмм (local-hash-128), это не локальная модель; в отчёте сам сказано, что прироста качества нет. Если hash-baseline принимается как «локальные эмбеддинги», это нужно зафиксировать решением оркестратора/правкой критерия; если нужна локальная модель — реализовать ONNX/WASM (или Ollama как локальную модель, но он сетевой HTTP и NO_NETWORK его запрещает). Сейчас критерий 2 в буквальной формулировке не выполнен.
  
  4) Критерий 3 «предупреждение в doctor»: реального doctor-команды/точки врача в основном пакете нет, doctorReport только пишет строки в лог при apply. Если doctor приходит отдельной задачей, это надо явно зафиксировать в карточке; иначе критерий не проверяется.

  Не блокирует, к сведению: live-событие entries-changed не реализовано (ленивый досчёт), в отчёте latency недетерминирована; локальный хэш не даёт качества; trust-boundary тест сканирует только lib/*.js верхнего уровня и не ловит динамические импорты/bin; package.json и docs — общие файлы; optional-пакет лежит в packages/, в npm-пакет основного не входит (это ок, но установка/публикация отдельная).
