  Возврат: doctor не выполняет критерий 2 в реальном пути плагина/CLI, и статус local-onnx неверен для model_path/NO_NETWORK. Проверил сам: npm test 284/284 на Node 25.1 и 24.21; backfill-прогресс, retry по entriesChanged, first-download warning, тесты — зелёные. Но:
  
  1) Число векторов показывает только doctorReport/doctorCommand при переданном `store`; в реальном apply вызов `doctorReport(options, { provider })` без store (packages/dsh-memory-embeddings/lib/index.js:125), а CLI `dsh-memory-embeddings doctor --config` без `--store` его не передаёт. Значит обычный doctor/лог плагина не показывают «число векторов/без векторов», хотя критерий 2 этого требует. Нужно либо открывать store для doctor (workspace/namespace/db_path) и передавать, либо добавить в doctorCommand опции store и тест реального CLI-пути; текущий тест передаёт store напрямую и обходит этот пробел.
  
  2) doctorReport local-onnx не знает `model_path`/NO_NETWORK: provider из createProvider не содержит model_path, doctorReport смотрит только isModelCached → при локальном model_path он скажет «нет в кэше» и покажет предупреждение о первой загрузке. При `DSH_MEMORY_NO_NETWORK=1` без кэша doctorReport тоже покажет «первая загрузка ~100 МБ», хотя скачивание запрещено и должен быть warn про FTS5. Нужно передать model_path и env/networkAllowed в doctorReport и тестировать оба случая; сейчас тесты покрывают только cache/no-cache без model_path/NO_NETWORK.
  
  3) Async-канал после ошибки backfill всё равно делает `prepared.add(store)` (packages/dsh-memory-embeddings/lib/channel.js): backfillEmbeddings ловит ошибку и возвращает failed, а search не проверяет summary. Поэтому утверждение заметки «после ошибки не кэширует успех» неверно; повтор возможен только после entriesChanged (тест вызывает его вручную).
