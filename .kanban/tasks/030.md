- 2026-11-11 (оркестратор, из ревью 026): учесть при приёмке фазы 5 —
  1) `planTimeoutMs` не отменяет сам planner (нет отдельного AbortController):
     планировщик может продолжать работу после fallback-а; нужен timeout-сигнал;
  2) причина таймаута/PlanError в live-обёртке теряется (`reason` = «план не покрыт
     ролями»), реальная причина только в warning-логе;
  3) `max_subtasks` обрезает план молча, без warning;
  4) объект подтемы без `role` даёт PlanError даже при `default_role` — поведение
     зафиксировать в дизайне.

- 2026-11-11 (оркестратор, из ревью 027): учесть при приёмке фазы 5 —
  1) после `Promise.all` dispatch не перепроверяет `signal.aborted`: отмена между
     ответом роли и агрегацией может вернуть ответ; закрыть контракт (тест);
  2) live-обёртка теряет различие `role timeout` / `provider failed` в `reason`;
  3) таймер role timeout всё ещё `unref` (в 024 для роутера снимали) — выровнять;
  4) `AbortError` от провайдера роли трактуется как отмена хода, а не ошибка роли.

- 2026-11-11 (оркестратор, из ревью 029): при приёмке учесть —

     insert; закрыть уникальностью или транзакцией);
  2) в shared-режиме verifyRole по id может подтвердить любую запись общего
     namespace при валидном verified_by — политику оговорить;
  3) docs §Namespace говорит «провенанс обязателен», а writeRole без sources
     создаёт draft 0.3 — уточнить формулировку.
