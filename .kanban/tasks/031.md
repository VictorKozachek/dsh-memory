## Задача
Регистрация memory.* в ctx.tools

Зависит от: 004–007, 012, 028. Спека: `.kanban/specs/001-mvp.md`, разделы 5.3/004–007.

Сейчас плагин отдаёт сервис `ctx.memory` (функции `searchMemory`, `write` и т.д.),
но **не регистрирует инструменты в `ctx.tools`** — модель не может вызвать
`memory.search`/`memory.write` сама. Инъекция (010) работает, но ручной доступ к
памяти агента отсутствует, хотя README и спека §4 обещают инструменты.

## Критерии готовности
- [ ] `apply` регистрирует инструменты `memory.search`, `memory.write`, `memory.verify`, `memory.invalidate`, `memory.stats` через `ctx.tools.register(defineTool(...))`; регистрация опциональная (нет сервиса `tools` — плагин грузится без него)
- [ ] схемы входа/выхода соответствуют контрактам README (search: query/k/kinds/status/namespace → массив сниппетов; write: text/title/kind/sources/confidence/status → id/deduped/status и т.д.)
- [ ] инструменты работают в namespace текущего хода (воркспейс сессии), search асинхронный, write не пишет `verified`, verify требует источник и `verified_by`
- [ ] описания инструментов для модели короткие и честные (по умолчанию только `verified`, сниппеты ≤ 300 символов)
- [ ] тест: регистрация на mock `ctx.tools`, `execute` каждого инструмента, валидация схем, ошибка возвращается как ошибка инструмента и не роняет ход
- [ ] README-таблица инструментов остаётся правдой (после задачи `memory.*` реально доступны агенту); docs/architecture при необходимости
