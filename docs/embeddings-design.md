# Дизайн: опциональный пакет эмбеддингов (`dsh-memory-embeddings`)

Статус: дизайн-спайк задачи 021; реализация 016 — `packages/dsh-memory-embeddings`
(см. §12).
Дата решения: 2026-11-10. Основание: `.kanban/specs/002-rag-ingest.md`,
[PLAN.md](../PLAN.md), отчёт [benchmark-real.md](benchmark-real.md).

## 1. Решение

Эмбеддинги — **отдельный опциональный бандл** `dsh-memory-embeddings`.
Основной пакет `dsh-memory` остаётся без сетевого кода, без ключей и без
провайдеров: пользователь, который не ставит опциональный пакет, не видит ни
провайдеров, ни их конфига. При выключенных/неустановленных эмбеддингах поиск —
ровно текущий FTS5 (BM25 + Snowball/trigram/синонимы/Q&A), поведение и цифры не
меняются.

Почему не в основном пакете: сетевой egress, ключи и зависимость от модели —
это отдельная поверхность доверия. Основной пакет должен оставаться
устанавливаемым в закрытом контуре и проверяемым тестом «в `lib/` нет ни
одного сетевого вызова».

## 2. Раскладка пакетов

```
dsh-memory/                  # основной, без сети
  lib/index.js               # apply(ctx, config), сервис ctx.memory
  lib/store.js               # SQLite, миграции; миграция 4 — таблица embeddings
  lib/search.js              # FTS5 + каналы поиска (расширение 016)
  cordis.patch.yml           # ряд dsh-memory

dsh-memory-embeddings/       # опциональный, весь egress здесь
  package.json               # dsh.bundle.patch, exports lib/index.js
  cordis.patch.yml           # ряд dsh-memory-embeddings после dsh-memory
  lib/index.js               # apply: конфиг, провайдер, канал поиска, doctor
  lib/providers/*.js         # openai-compatible, ollama, local-onnx
  lib/backfill.js            # очередь/бэкфилл векторов
```

Опциональный пакет **зависит от основного** (`peerDependencies`/dependency на
`dsh-memory`), обратной зависимости нет. Основной пакет не знает имён
провайдеров и не импортирует `dsh-memory-embeddings`.

### Точка монтирования

`dsh-memory-embeddings` объявляет собственный `dsh.bundle.patch`:

```yaml
# cordis.patch.yml пакета dsh-memory-embeddings
- insert:
    - id: dsh-memory-embeddings
      name: dsh-memory-embeddings
      config:
        enabled: false          # дефолт — выключено
        provider: ""            # openai-compatible | ollama | local-onnx
        base_url: ""
        model: ""
        api_key_env: DSH_MEMORY_EMBEDDINGS_API_KEY
```

Установка: `dsh plugin --profile <имя> add dsh-memory-embeddings` (или
аналогичная команда установки бандла). После установки и `enabled: true`
пакет монтируется после `dsh-memory`, получает сервис `memory` и регистрирует
свой канал поиска. Удаление пакета возвращает ровно FTS5.

### Публичный API основного пакета для опционального

В 016 основной пакет добавляет **только нейтральные к сети** точки расширения:

- `ctx.memory.storeFor(cwd)` — открыть/взять `MemoryStore` для воркспейса
  (тот же кэш, что у инъекции; без нового поведения по умолчанию);
- событие `memory/entries-changed` (`{ namespace, ids }`) после `write`,
  `verify`, `invalidate` и переиндексации — опциональный пакет по нему
  досчитывает векторы;
- `ctx.memory.registerSearchChannel(channel)` — канал `{ name, search(ctx) }`,
  который `memory.search` опрашивает после FTS5 и сливает результаты;
- экспорт `./network` (см. §7) для проверки `DSH_MEMORY_NO_NETWORK`.

Основной `memory.search` при отсутствии зарегистрированных каналов работает
байт-в-байт как сейчас (это регресс-тест 016).

## 3. Конфиг

Конфиг живёт **в ряду опционального пакета**, не в `dsh-memory`:

| Поле | Тип | Дефолт | Смысл |
|---|---|---|---|
| `enabled` | boolean | `false` | включить гибридный поиск |
| `provider` | `""` \| `openai-compatible` \| `ollama` \| `local-onnx` | `""` | бэкенд; без него ошибка конфига |
| `base_url` | string | `""` | для API/Ollama; обязателен для `openai-compatible`, у Ollama дефолт `http://127.0.0.1:11434` |
| `model` | string | `""` | id модели; обязателен при `enabled` |
| `api_key_env` | string | `DSH_MEMORY_EMBEDDINGS_API_KEY` | **имя** переменной с ключом, не значение |
| `batch_size` | int | `32` | размер батча при индексации/запросе |
| `timeout_ms` | int | `5000` | таймаут запроса к провайдеру |
| `max_retries` | int | `2` | повторы для API (не для локальной модели) |
| `hybrid_weight` | number | `0.5` | вес векторного канала при взвешенном слиянии |

Валидация не роняет загрузку профиля (правило проекта «плагин не ломает ход»):
при `enabled: true` и отсутствии `provider`/`model`/`base_url` (где нужен) или
ключа в env пакет пишет `warn`, `doctor` показывает причину, гибридный канал не
регистрируется, `memory.search` продолжает работать на FTS5.

Легаси-поле `embeddings: { enabled, model }` в конфиге основного пакета
(`lib/config.js`) не используется для сетевых вызовов и помечается deprecated:
источник истины — ряд `dsh-memory-embeddings`. В 016 оно игнорируется
(или удаляется отдельной миграцией конфига).

## 4. Схема `embeddings`

Таблица добавляется миграцией 4 основного пакета: это схема хранилища, а не
провайдер; в ней нет ни URL, ни ключей, ни сетевого кода. Опциональный пакет
только читает/пишет строки.

```sql
CREATE TABLE embeddings (
  entry_id   INTEGER NOT NULL REFERENCES entries(id) ON DELETE CASCADE,
  model      TEXT    NOT NULL,          -- id модели/версии
  dim        INTEGER NOT NULL,          -- размерность
  vector     BLOB    NOT NULL,          -- float32 little-endian, длина dim*4
  created_at INTEGER NOT NULL,
  PRIMARY KEY (entry_id, model)
);
CREATE INDEX embeddings_model ON embeddings(model);
```

Инварианты: `dim = length(vector)/4`, все компоненты конечны; при смене
модели/размерности строки старой модели не смешиваются с новой (поиск идёт
только по `model`, выбранной в конфиге). Вектор entry-level: для `doc`-чанков
эмбеддится `title + text` чанка; для `fact`/`decision`/`answer` — `title +
text`. Для запроса эмбеддится текст запроса (до 200 символов, как инъекция).

## 5. Гибридный скор BM25 + косинус

Кандидаты: FTS5 top-N (N = max(50, 4k)) и векторный top-M (M = max(50, 4k)).
Дедупликация по `id`. Итоговый скор — **reciprocal rank fusion** по умолчанию:

```
score(d) = 1/(60 + rank_lex(d)) + w_vec * 1/(60 + rank_vec(d))
```

RRF не требует согласовывать шкалы bm25 и косинуса. Альтернатива
(`hybrid_weight`): min-max нормировка bm25 по кандидатам и
`score = (1-w)*norm_lex + w*cos`, но она чувствительна к выбросам; в 016
реализуется RRF, взвешенный вариант — только если понадобится по бенчмарку.

Косинус считается по нормализованным векторам; при `||v||=0` — 0. Q&A-канал
020 (verified-ответы по заголовку) остаётся отдельным бустом и не участвует в
векторном слиянии. При выключенных эмбеддингах, ошибке провайдера или пустой
таблице `embeddings` результат — чистый FTS5 (fallback без изменения выдачи).

## 6. Бэкенды

| Провайдер | Как работает | Сеть | Ключ |
|---|---|---|---|
| `openai-compatible` | `POST {base_url}/embeddings` `{model,input}` → `data[].embedding`; батчи, таймаут, retry 429/5xx | только этот пакет | `env[api_key_env]`, заголовок `Authorization: Bearer …` |
| `ollama` | `POST {base_url}/api/embeddings` локального Ollama | локальный HTTP (NO_NETWORK запрещает) | не нужен |
| `local-onnx` | WASM/ONNX-модель в процессе, например `multilingual-e5-small` (квантованная); модель ставится заранее/бандлом | нет | не нужен |

`local-onnx` — рекомендуемый offline-дефолт, если модель уже на диске; скачивание
модели при первом запуске — отдельное явное действие, а не скрытый egress.
Ollama удобен для тех, у кого он уже есть, но с `DSH_MEMORY_NO_NETWORK=1`
запрещён (строгий режим означает «никакого сетевого стека», включая localhost).

### Ключ

- В конфиге хранится **имя** переменной (`api_key_env`), не ключ.
- Значение читается из `process.env` в момент вызова; в БД, настройки, логи,
  `doctor`, `metrics`, карточки задач и сообщения об ошибках не попадает.
- Ошибки провайдера логируются с редактированием заголовков и тела
  (`Authorization`, `api_key`, `token` → `***`); тест на редактирование.
- Пустой/незаданный ключ — это конфигурационная ошибка, а не «попробуем без
  ключа»: канал выключается, остаётся FTS5.

## 7. Границы доверия и сеть

1. **Основной пакет без сети.** `test/trust-boundary.test.mjs` сканирует
   `lib/**/*.js` основного пакета на `node:http(s)`, `node:net`, `node:tls`,
   `node:dgram`, `fetch(`, `undici`, `axios`, `openai` и проверяет, что в
   `package.json` нет сетевых зависимостей. Ревью 016 обязано сохранить тест
   зелёным.
2. **Весь egress — только в `dsh-memory-embeddings`.** В основном пакете нет ни
   одной строки, которая открывает соединение.
3. **`DSH_MEMORY_NO_NETWORK=1`** (`true`/`on`/`yes`) запрещает сеть. Пакет
   вызывает `assertNetworkAllowed()` из `dsh-memory/network` перед любым
   HTTP-запросом и при флаге не делает его; локальный WASM/ONNX без сети
   разрешён. Тест 016 с мок-сервером: при флаге ни одного запроса.
4. **Данные наружу.** При включённом сетевом провайдере наружу уходят текст
   запроса и тексты записей при индексации. Это явное предупреждение в
   `doctor`, а не тихий дефолт; политика приватности — на пользователе.

## 8. Сценарий включения и `doctor`

```
embeddings.enabled = false            -> FTS5 (дефолт, ничего не меняется)
enabled=true, provider/model пустые   -> warn + doctor: не включено, FTS5
enabled=true, API, нет ключа в env    -> warn + doctor: нет <ENV>, FTS5
enabled=true, API, ключ есть          -> hybrid; doctor предупреждает об отправке
enabled=true, local-onnx, модели нет  -> warn + doctor: модель не найдена, FTS5
enabled=true, DSH_MEMORY_NO_NETWORK=1 -> egress запрещён, remote-провайдер не
                                          используется; local-onnx — можно
```

`doctor` (в основной пакет команда приходит отдельной задачей; в 016 — проверка
embeddings-пакета) печатает:

```
embeddings: включены (provider=openai-compatible, model=text-embedding-3-small)
ВНИМАНИЕ: запросы и тексты записей будут отправлены провайдеру <host>.
Ключ берётся из env <ENV> (значение не показывается).
```

или причину отключения/отката. Никаких значений ключа в выводе.

## 9. Индексация и фоновый бэкфилл

- При старте пакет ищет записи без строки `embeddings` для выбранной модели и
  ставит их в очередь (батчами, с ограничением параллелизма).
- Событие `memory/entries-changed` добавляет/обновляет id; `stale`/удалённые
  записи удаляются каскадом/очередью очистки.
- Инъекция (010) не должна ждать эмбеддинг: если вектора нет, запись всё равно
  находится по FTS5; досчёт идёт фоном. Таймаут запроса к провайдеру на
  критическом пути — не больше `timeout_ms` (по умолчанию 5 с), при
  превышении — fallback FTS5 для этого хода.
- Переиндексация `doc`-чанков (014/003) меняет текст → новые эмбеддинги;
  старые строки удаляются по `entry_id`.

## 10. Критерии приёмки 016

1. Отдельный пакет `dsh-memory-embeddings` с собственным `dsh.bundle.patch`;
   установка/удаление не меняет основной пакет; по умолчанию выключено.
2. Основной пакет: тест `trust-boundary` зелёный; `lib/` без сетевых импортов и
   вызовов; новых зависимостей нет.
3. `DSH_MEMORY_NO_NETWORK=1` запрещает egress: мок-сервер не получает ни одного
   запроса; ошибка понятна, поиск откатывается на FTS5.
4. Таблица `embeddings` (миграция 4), запись/чтение BLOB, `dim`/`model`
   валидируются; смена модели не смешивает размерности.
5. Гибридный поиск улучшает реальный бенчмарк 022 (`docs/benchmark-real.md`):
   hit-rate выше FTS5 при том же списке вопросов, отчёт
   `docs/benchmark-embeddings.md`; цель — не хуже FTS5 и рост hit-rate на
   смысловых промахах.
6. Латентность: p95 добавки к поиску ≤ 50 мс на реальном корпусе (или явно
   отражена цена в отчёте; инъекция не блокируется дольше `timeout_ms`).
7. Fallback: нет ключа/base_url/модели, ошибка провайдера, таймаут, пустая
   таблица → результаты и вид `memory.search` совпадают с FTS5; `doctor`
   объясняет причину.
8. Ключ не попадает в БД, логи, ошибки, карточки и `metrics`; тест на
   редактирование секретов.
9. Бэкенды: `openai-compatible` (мок-сервер, без реальной сети), `ollama`
   (мок локального API), `local-onnx` (маленькая тестовая модель/заглушка);
   offline-режим тестируется без сети.
10. README/README.en, конфиг, миграция и отчёт обновлены; удаление пакета
    возвращает чистый FTS5.

## 11. Открытые вопросы

1. **Дефолтный провайдер.** Предложение: дефолта нет (`enabled:false`,
   `provider:""`); рекомендуемый путь — `local-onnx`, но модель не тянется
   автоматически. Нужен явный выбор владельца.
2. **Локальная модель.** `multilingual-e5-small`/`e5-base` (лицензия, размер,
   качество на русском) vs специализированная русская; квантование и формат
   ONNX; где хранить модель (пакет/`$DSH_HOME/models`) и как проверять
   целостность.
3. **Порог brute-force → ANN.** Старт — brute-force косинус по SQLite BLOB.
   ANN (`sqlite-vec`) — когда векторный поиск p95 > 50 мс или строк > 50 000;
   решение по замеру, не заранее. Нужен бенчмарк на реальном корпусе.
4. **Гранулярность.** Entry-level (текущий дизайн) vs чанки `doc`; для длинных
   чанков (800 токенов) качество эмбеддинга падает — возможно, уменьшить
   `max_chunk_tokens` или эмбеддить summary.
5. **Смена модели/размерности.** Держать строки по `(entry_id, model)` и
   бэкфиллить лениво; вопрос — удалять ли старые модели сразу.
6. **Приватность.** Запросы могут содержать секреты; нужен ли redaction перед
   отправкой провайдеру и как он сочетается с уже отсеянными секретами файлов.
7. **Стоимость и лимиты.** Батчи, кэш эмбеддингов запроса, rate limit, бюджет
   на фоновый бэкфилл; что делать при 429.
8. **Композиция с Q&A-каналом 020** и с каскадом 012: где именно буст
   Q&A/вектора складываются, чтобы не переранжировать проверенные ответы.


## 12. Что реализовано в 016 и чем отличается от дизайна

- Пакет `packages/dsh-memory-embeddings` с собственным `dsh.bundle.patch`,
  конфигом, провайдерами `local` (встроенный офлайн-хэш-эмбеддер
  `local-hash-128`), `ollama` и `openai-compatible`, таблицей `embeddings`
  (миграция 4 основного пакета), бэкфиллом и brute-force косинусом.
- Основной пакет получил нейтральные точки `memory.storeFor`,
  `memory.registerSearchChannel`, `channels` в `memory.search` и миграцию 4 —
  без сетевого кода (тест `trust-boundary` остаётся зелёным).
- Каналы: `local` — синхронный, `openai-compatible`/`ollama` — асинхронный;
  hook использует `buildMemoryBlockAsync`, поэтому API-бэкенд тоже даёт
  гибридный RRF, а не только backfill. Синхронный `memory.search` async-каналы
  пропускает.
- `local` — офлайн-baseline (хэш слов/триграмм), не нейросетевая модель;
  локальная модель — `local-onnx` (обязательный `model_path`, `allowRemoteModels=false`)
  или `ollama` (HTTP localhost; NO_NETWORK запрещает). Реальная ONNX-модель в
  отчёте 016 не замерялась (нет артефакта); это граница для 016/021.
- Сервис `memory.search` основного пакета стал асинхронным и ждёт async-каналы;
  `memory.searchSync` сохраняет синхронный контракт для CLI/бенчмарка.
- Событие `memory/entries-changed` из §2 пока не реализовано: локальный канал
  лениво досчитывает, API/Ollama — при первом поиске по store; live-обновление
  при write/verify — следующий шаг.
- Нейросетевая локальная модель (ONNX/WASM) и ANN остаются открытыми
  вопросами 021; отчёт [benchmark-embeddings.md](benchmark-embeddings.md)
  фиксирует baseline и цену опции.
