# Жёсткий роутер L2→L3 (задача 017)

Статус: дизайн-док и прототип. Реализация — `lib/router.js`; фича-флаг
`router.enabled` по умолчанию **выключен**. Зависит от 012 (мягкий каскад) и
015 (бенчмарк).

## 1. Решение

После L1 (память/инъекция) ход обслуживает либо дешёвая L2 (пресет `triage`),
либо основная L3. Мягкий каскад 012 спрашивает L2 и при `NO_ANSWER` идёт
дальше; жёсткий роутер добавляет **порог уверенности**: если L2 вернула ответ с
`confidence >= router.confidence_threshold`, ход остаётся на L2, иначе
безусловно вызывается L3. Это детерминированное решение, а не «надеемся, что
модель скажет NO_ANSWER».

Флаг выключен по умолчанию: L2 не вызывается, поведение совпадает с текущим
дефолтом (прямой L3 после L1). Включение — осознанное решение владельца
профиля, после калибровки порога бенчмарком.

## 2. Точка входа хода

```
agent/pre-step ──► L1: memory.search / инъекция (010, 012)
                         │ попадание — ответ из памяти, модели не нужны
                         ▼ промах
                 routeTurn({query, providers, config, signal})
                         │
             router.enabled? ──нет──► L3 напрямую
                         │ да
                         ▼
                 L2 (triage) с таймаутом/отменой, буферизуется
                         │ confidence >= threshold
                         ├── да ──► L2, route{L2}, ответ
                         └── нет / NO_ANSWER / error / timeout
                                     ▼
                              L3, route{L3}, стриминг ответа
```

`routeTurn` — чистый модуль с инъекцией провайдеров: основной пакет не зависит
от `dsh-llm`; адаптер провайдеров появится в интеграционной задаче. Прототип
не меняет `apply`/hook автоматически: вызов роутера — решение вызывающего хода
(в 012/017 интеграция остаётся явной, чтобы выключенный флаг гарантировал
отсутствие регрессии).

## 3. Контракт провайдеров

```js
providers.l2({ query, signal }) -> {
  status: 'ANSWER' | 'NO_ANSWER',   // строка 'NO_ANSWER' тоже допустима
  answer: string,
  confidence: number,               // 0..1
  tokensSavedEstimate?: number      // оценка экономии L2 вместо L3
}
providers.l3({ query, signal, reason, onToken }) -> { answer, confidence }
```

- Строковый ответ провайдера трактуется как `ANSWER` с `confidence = 1`
  (обратная совместимость с простыми адаптерами); объект без `confidence` —
  `confidence = 0`, то есть роутер уйдёт на L3 (консервативно).
- `onToken` у L3 — поток токенов; у L2 в режиме роутинга не используется.
- `signal` — `AbortSignal`: отмена хода или таймаут.

## 4. Стриминг

- **L2 буферизуется.** Отдать пользователю токены L2, а потом решить «не
  уверена» и пойти в L3 нельзя: получится два ответа. Поэтому L2 вызывается без
  стриминга (или адаптер копит токены и отдаёт их только после решения).
- **L3 стримится.** После решения `routeTurn` пробрасывает `onEvent({type:
  'token', layer:'L3', token})`; потребитель хода пишет их в тот же поток, что и
  обычно.
- События `route` (`layer`, `reason`, `confidence`) отправляются до токенов L3,
  чтобы UI успел показать выбранный слой.

## 5. Отмена

- Внешний `AbortSignal` проверяется до вызова L2 и внутри `callWithTimeout`.
- Отмена на L2 **не** уходит в L3: ход отменён пользователем, а не «L2 не
  справилась». Наружу — `AbortError`.
- Отмена на L3 пробрасывается провайдеру; роутер не подменяет её на L2.
- Таймеры таймаутов очищаются, listener отмены снимается; таймеры `unref`,
  чтобы не держать процесс.

## 6. Таймауты

| Что | Значение | Поведение |
|---|---|---|
| L2 (`router.timeout_ms`) | 5000 мс по умолчанию | по таймауту `route{L3, 'L2 timeout'}`, затем L3 |
| L3 (`router.timeout_ms`) | тот же | ошибка таймаута наружу; повтор/фоллбек — решение вызывающего |

Таймаут L2 не означает «L2 плохая»: он означает «не успела», поэтому L3 — это
fallback качества. Таймаут L3 — ошибка хода, а не повод молча ответить пустым.

## 7. Метрики и логирование

Решение пишется в `metrics` как `route` (011):

```json
{ "layer": "L2", "reason": "confident", "tokens_saved_estimate": 500,
  "injected_tokens": 0 }
```

- `L2` — экономия (`tokens_saved_estimate` из ответа провайдера); `L3` — 0.
- Причины: `confident`, `L2 no answer`, `L2 low confidence (0.42)`,
  `L2 timeout`, `L2 error`, `L2 unavailable`, `router disabled`.
- Логи содержат только слой/причину/уверенность; текст запроса и ответа не
  пишется (приватность и размер лога).
- `stats` 011 суммирует route-события: L2 savings видны, L1-инъекция — расход.

## 8. Конфиг

```yaml
router:
  enabled: false            # фича-флаг, дефолт выключен
  confidence_threshold: 0.6 # 0..1
  timeout_ms: 5000          # L2 (и L3) таймаут
```

Невалидные значения заменяются дефолтами с предупреждением (общая политика
конфига 008). Флаг выключен — L2 не вызывается, `route{L3, router disabled}`
пишется для наблюдаемости.

## 9. Прототип и тесты

`lib/router.js` экспортирует `routeTurn`, `resolveRouterConfig`,
`ROUTER_DEFAULTS`, `RouterTimeoutError`. Тесты `test/router.test.mjs`:

- выключенный флаг: L3, L2 не вызван, route-метрика;
- уверенный L2: L3 не вызван, savings в route;
- низкая уверенность / `NO_ANSWER` / ошибка / таймаут L2 → L3 с причиной;
- таймаут L3 → ошибка; отмена до L2 → `AbortError`, L3 не вызван;
- стриминг: токены L2 не утекают, L3 приходят в порядке;
- пустой ответ L3 — ошибка контракта; валидация конфига.

## 10. Взаимодействие с 012 (мягкий каскад)

`cascade.enabled` и `router.enabled` — независимые флаги:

- оба выключены: L1 → L3 (текущий дефолт);
- `cascade.enabled`, router off: L1 → L2 → L3 по `NO_ANSWER` (012);
- `router.enabled`: L1 → `routeTurn` (жёсткий порог) → L2/L3.

Одновременное включение допустимо, но вызывающий ход должен выбрать один
механизм, иначе L2 будет вызвана дважды. В интеграционной задаче это
фиксируется в точке входа: жёсткий роутер имеет приоритет, если включён.

## 11. Открытые вопросы

1. Калибровка `confidence_threshold` на реальном корпусе (бенчмарк 015/022):
   порог должен максимизировать долю L2 при отсутствии роста ошибок.
2. Стриминг L2: разрешить адаптеру копить токены и отдавать их после решения
   (сейчас L2 вызывается без `onToken`).
3. Пер-ролевой порог/флаг (диспетчер 018): возможно, для ревью нужен L3 всегда.
4. Таймаут L3 и политика ретраев: сейчас ошибка наружу; нужен ли один retry.
5. Логирование route-событий в `metrics` уже есть; нужен ли отдельный счётчик
   «доля L2» в `stats` (сейчас `memoryStats` не отдаёт by_layer).
6. Отмена и стриминг в реальном провайдере DSH: `AbortSignal` должен доходить
   до HTTP-запроса; проверить на адаптере 017.
